How AI LOTO Monitoring Operates

This section explains what happens after BioStar 2 reports a successful worker authentication, how ENTER/EXIT is decided, and how physical outputs are sequenced.

1. Successful authentication flow

Duplicate protectionExternal BioStar event IDs are treated as idempotent, and rapid repeated events for the same user + device are suppressed inside the configured BioStar Event Debounce Window (default 1 second).

2. How ENTER and EXIT are determined

The scanner does not have a permanent â€œINâ€ or â€œOUTâ€ direction. The system uses the workerâ€™s active state:

No active worker state

The accepted scan is TAG_IN. The worker becomes registered inside and the gate associated with the scanning access device is opened through the safe gate sequence.

Worker already active inside

The accepted scan is TAG_OUT. The active worker state is cleared. Gate close behavior depends on the session and whether other workers remain inside.

Normal one-gate example

  1. Worker authenticates at Gate 1 while not registered inside.
  2. LOTO records IN, creates/joins the Gate 1 session and commands Gate 1 to open.
  3. When the worker later authenticates again and is still active, LOTO records OUT.
  4. If this makes the session count zero, Gate 1 is commanded to close. If other workers remain in that session, no close command is issued yet.

Cross-gate example

Current cross-gate ruleA worker can enter through one gate and authenticate at a different gate to exit. The active session remains associated with the original entrance gate.
  1. Worker enters through Gate A; worker is active inside.
  2. The same worker later authenticates at Gate B. Because the worker is already active, this is interpreted as OUT, not another IN.
  3. If no active workers remain from the original entrance gate, LOTO closes the original session gate (Gate A).
  4. The scanning gate (Gate B) is not closed for this inside-to-outside cross-gate exit in the current deployment, because the installed scan path is treated as one-way outside access.

AUX feedback is authoritativeLOTO does not report a transition complete just because it successfully wrote an output. The configured FlexLock AUX input is the feedback used to advance the open/close sequence.

Timeout, retry and FAULT

Temporary SIG300 communication errors are retried automatically without restarting the whole gate sequence. Manual gate operations wait up to 15 seconds for the command to complete. Gate commands triggered by BioStar can retry up to 3 times if they time out. If the operation still cannot complete, the gate enters FAULT state, and the failed step is shown in Monitoring and Gate Management so the operator can retry it.

5. Manual Open / Close

Manual commands from Gate Management use the same physical sequences above. They are useful for controlled maintenance or recovery, but they do not add or remove workers from the active-worker list. Worker presence is managed by accepted authentication events or an authorized manual Tag Out operation.

6. Alarm gateway output meanings

Alarm outputs are logical functions mapped to pins on all Gateway Devices with role Alarm. All outputs initialize to their configured startup default; the standard topology uses LOW/OFF.

Logical output HIGH / ON condition in current code Operational meaning
Green Registered workers = 0 and all gates are closed, while required alarm facts are known. No registered workers inside; gates are closed.
Orange Registered workers > 0 and AI detected people = 0, while required alarm facts are known. Workers are registered but AI currently sees no people.
Red Registered workers > 0 and AI detected people > 0, while required alarm facts are known. People are registered and AI detects people.
Fall Fall state active and at least one gate is open. Fall alarm condition during gate-open monitoring.
Mismatch Registered worker count < AI detected people count and a gate is open. AI detects more people than are registered inside.

Outputs are evaluated independently. For example, Red can be ON at the same time as Fall and/or Mismatch. If required safety facts are not available after startup, the software keeps the logical alarm outputs LOW rather than inventing a â€œsafeâ€ state.

7. Site Safety Status

UNKNOWN

Required facts are incomplete or do not yet form a classified state.

SAFE

Trusted sources available; no workers/AI people inside; all gates closed; no active fall/mismatch/transition/fault.

WARNING

Sources are available; workers are inside and the registered count matches the AI count.

UNSAFE

Camera or Alarm Gateway unavailable, gate state unknown, AI count exceeds registered workers, or gate fault is active.

System Trust shows GOOD when required monitoring sources are sufficiently available/current; otherwise it shows NG. Treat N/A/NG as a data-quality or source-availability condition, not as zero people.

8. Visionary AI processing

Configured Visionary cameras provide two independent kinds of information:

  • People count: people are counted only from configured people-count evaluation/volume ID. Unavailable camera data is not converted to zero.
  • Fall detection: configured fall evaluation ID use the Visionary Field Evaluation state.
